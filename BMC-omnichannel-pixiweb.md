# Business Model Canvas — Omnichannel Pixiweb

Fecha: 2026-10-10. Borrador basado en pedido; sin investigación comercial de campo.

| Bloque | Definición |
|---|---|
| Segmentos | S1: negocios que captan consultas en Instagram/Facebook/web y atienden por WhatsApp. S2: agencias que administran esos canales para varios clientes. Hipótesis de destinatarios, no segmentos validados |
| Propuesta de valor | S1: atender y automatizar desde un inbox, pasar de comentario a conversación y mantener CRM. S2: separar cuentas, permisos y datos por cliente sin repartir el trabajo entre herramientas |
| Canales | Entrega web SaaS; cada cliente conecta Meta y Brevo. Adquisición comercial pendiente de definir |
| Relaciones | Autoservicio guiado con diagnóstico de conexión; soporte administrativo para permisos y errores; atención al consumidor a cargo del cliente |
| Ingresos | Modelo SaaS declarado; posible suscripción por workspace y consumo, todavía hipótesis. Sin precio, cobro, planes nuevos ni checkout en este alcance |
| Recursos | Fork MIT, mantenimiento técnico, app/negocio Meta, Supabase, hosting, proveedores WA, IA y Brevo de cada cliente |
| Actividades | Operar inbox, asegurar aislamiento, mantener integraciones, revisión de API, soporte y observabilidad |
| Alianzas/dependencias | Meta, YCloud/Kapso, Brevo, Supabase, hosting y modelos; no implica partnership comercial |
| Costos | Hosting/BD/storage, IA, proveedor WA, mantenimiento, soporte y planes externos aplicables. Medir consumo; no se asume gratuidad |

## Alineación con VPC

- [x] S1 y S2 tienen perfil y propuesta.
- [x] La hipótesis de suscripción corresponde al servicio omnicanal, sin ventas prometidas.
- [x] Jobs asignados a S1/S2.
- [x] Valor limitado a capacidades especificadas, sin prometer conversiones.
- [x] Pains/gains no cubiertos tienen disposición explícita.
